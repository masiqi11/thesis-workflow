# Known Issues / 历史问题尸账

本文档记录此前在真实任务中踩过的坑与对应规避策略。SKILL.md 不再内联这些条目；
所有新坑都应在此追加，并在相关子 Skill 章节脚注中引用本文件。

## 1. 标题编号重复
- 现象：Markdown 已写 `1.1`，脚本又自动补编号
- 根因：未先剥离已有编号
- 规避：进入生成层前统一 `strip_heading_number`

## 2. 标题体系与模板不一致
- 现象：生成的是 `第一章/1.1`，模板要求 `一、/（一）/1.`
- 根因：按技术文档习惯实现，不是按用户模板实现
- 规避：一切以 intake 明确后的文字规则为准

## 3. 插图触发条件过窄导致漏图
- 规避：图号首次出现即插图，不依赖固定措辞

## 4. 图号顺延后正文与映射脱节
- 规避：正文引用、映射、图题三处一起改

## 5. 新图已放入目录，但论文仍在用旧图
- 规避：优先覆盖旧文件名，否则同步修改映射

## 6. 图像展示性差
- 规避：必须做答辩可读性验收

## 7. Word 占用导致保存失败
- 规避：正式生成前关闭 docx，必要时输出 `_验收版.docx`

## 8. 参考文献格式与模板冲突
- 规避：以用户明确给出的文字规则为准，不擅自默认

## 9. 前置页与正文格式混杂
- 规避：封面、摘要、目录、正文、参考文献、致谢分段处理

## 10. 公式、表格、图题规则未提前锁定
- 规避：开工当天在 intake 中明确

## 11. 长上下文导致写作目标漂移
- 规避：多章写作优先 Team mode，拆章并行，主控统一收口

## 12. AI 编造文献或实验结论
- 规避：通过 `/thesis-citations` 与 `/thesis-audit` 强制联网核验

## 13. 前期数据准备缺少论文引用收集
- 现象：进入正文撰写时没有可用引用论文，导致引用空洞
- 根因：`/thesis-data` 未包含文献收集环节
- 规避：`/thesis-data` 强制要求论文引用收集，未就绪禁止进入 `/thesis-write`；
  优先国外论文便于下载；下载失败立即通知用户

## 14. 正文撰写与前期资源解耦
- 现象：正文写完后再插图，导致图与内容不对应、缺图、图号混乱
- 根因：写作与图表准备是独立步骤，未在写作时内联插图
- 规避：正文撰写时边写边插图，写前确认本章图号/表号/引用，缺图即补；
  资源未齐备不得动笔

## 15. 模板要求仅存于上下文，长任务中遗忘
- 现象：中后期写作偏离论文模板要求，格式错误频出
- 根因：格式要求未持久化，仅靠上下文记忆
- 规避：intake 阶段将所有格式要求写入 `template_requirements.md`，
  每次会话/子 Skill 启动时必须先读取此文件

## 16. 概念图与实验数据图生成策略混淆
- 现象：要求 Python 生成架构图（不合理），或用 AI 提示词生成实验曲线（不可复现）
- 根因：未区分两类图表的生成方式
- 规避：概念图（流程图/架构图）生成提示词；实验数据图用 Python 脚本从真实数据生成；
  二者不可混用

## 17. AI 率过高——过度结构化写作
- 现象：AI 检测率和查重率双高，全文充满"首先/其次/再次/此外/最后"机械递进、
  段落等长对称、每段总分总
- 根因：AI 默认倾向生成结构化、对称、均匀的文本，这是 AI 写作最显著的指纹
- 规避：段落长短交替、自然过渡不依赖连接词、有详有略、具体数据替代空话、
  术语替代通用表述、图文交叉打破文本墙
